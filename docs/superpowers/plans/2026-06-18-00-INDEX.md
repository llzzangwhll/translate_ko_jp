# 한↔일 통역 앱 구현 계획 — 인덱스 & 공유 계약

> 설계 스펙: `docs/superpowers/specs/2026-06-18-realtime-ko-jp-interpreter-design.md`

이 구현은 **플로우별 plan 파일**로 쪼개져 있고, 각 파일은 독립적으로 동작·테스트 가능한 결과물을 낸다. 아래 의존 그래프와 **공유 계약(Shared Contracts)** 을 모든 plan이 단일 진실 공급원으로 따른다.

## 실행 순서 & 병렬화

```
00 Foundation  (선행 필수: core 타입 + Service 인터페이스 + 엔티티 + DI 골격)
   │
   ├─ 01 번역 플로우      ─┐
   ├─ 02 모델 관리 플로우  ─┤  ← 00 완료 후 병렬 진행 가능 (서로 Fake로 격리)
   ├─ 03 히스토리 플로우   ─┤
   └─ 04 iOS 네이티브 추론 ─┘
   │
   05 통합 & 마무리 (라우팅 연결, E2E 스모크, 정리)  ← 01~04 머지 후
```

- **00 완료가 모든 병렬 작업의 게이트.** 인터페이스/타입이 확정돼야 각 플로우가 Fake에 기대어 독립 구현 가능.
- 01~04는 **서로 다른 파일/디렉터리**만 건드리도록 분해되어 머지 충돌이 최소.
- 공용 파일(`app/bindings.dart`, `app/routes.dart`)은 각 플로우가 **자기 항목만 추가**하고, 최종 연결은 05에서 정리.

  ko,
  ja;

  String get sttLocale => this == Language.ko ? 'ko_KR' : 'ja_JP';

### core/result.dart

```dart
import 'failure.dart';

sealed class Result<T> {
  const Result();

  bool get isOk => this is Ok<T>;
  T? get valueOrNull => this is Ok<T> ? (this as Ok<T>).value : null;
  Failure? get failureOrNull => this is Err<T> ? (this as Err<T>).failure : null;
}

class Ok<T> extends Result<T> {
  final T value;
  const Ok(this.value);
}

class Err<T> extends Result<T> {
  final Failure failure;
  const Err(this.failure);
}
```

### domain/entities/language_direction.dart

```dart
import '../../core/language.dart';

class LanguageDirection {
  final Language from;
  final Language to;
  const LanguageDirection({required this.from, required this.to});

  factory LanguageDirection.koToJa() =>
      const LanguageDirection(from: Language.ko, to: Language.ja);
  factory LanguageDirection.jaToKo() =>
      const LanguageDirection(from: Language.ja, to: Language.ko);

  LanguageDirection get reversed => LanguageDirection(from: to, to: from);
  bool get isKoToJa => from == Language.ko;

  @override
  bool operator ==(Object other) =>
      other is LanguageDirection && other.from == from && other.to == to;
  @override
  int get hashCode => Object.hash(from, to);
}
```

class DownloadProgress {
  final int received;
  final int total;
  final bool done;
  const DownloadProgress({
    required this.received,
    required this.total,
    required this.done,

### DI 바인딩 규약

- `app/bindings.dart`의 `AppBinding`에 Service→Repository→UseCase 순으로 `Get.lazyPut`/`Get.put` 등록.
- 각 플로우는 자기 의존만 등록하는 함수를 노출하고(예: `registerTranslationDeps()`), 05에서 `AppBinding`이 호출하도록 합친다.

### 테스트/명령 규약

- 단위·위젯 테스트: `flutter test test/<경로>` (예: `flutter test test/core/result_test.dart`).
- 모든 외부 의존은 인터페이스 → 테스트는 동일 디렉터리 규칙의 Fake 사용 (`test/fakes/`).
- 커밋 메시지: `feat:`/`test:`/`refactor:` 프리픽스, 한 태스크 = 한 커밋.
